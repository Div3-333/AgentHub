# System Architecture: The Phantom Terminal

To achieve robust orchestration of free-tier CLIs without APIs, AgentHub uses a highly specialized architecture focused on Process Control and Stream Sanitization.

## 1. High-Level Topology

```mermaid
graph TD
    UI[AgentHub TUI<br>(Ratatui)] <-->|Events| Core[Rust Orchestrator]
    
    Core <-->|PTY Stdin/Stdout| CLI1[gemini-cli<br>(Phantom Process)]
    Core <-->|PTY Stdin/Stdout| CLI2[cursor-cli<br>(Phantom Process)]
    Core <-->|PTY Stdin/Stdout| CLI3[aider<br>(Phantom Process)]
```

## 2. Component 1: The PTY Engine
Standard `stdio` piping (`Command::new().stdout(Stdio::piped())`) fails for interactive AIs. They detect they aren't in a real terminal and crash or buffer output forever.
*   AgentHub uses **Pseudo-Terminals (PTY)** via crates like `portable-pty`.
*   Every agent CLI is spawned inside its own invisible PTY. As far as `gemini-cli` is concerned, it is running in a standard Ubuntu or Windows terminal.

## 3. Component 2: The Driver Profiles
Every CLI is different. AgentHub uses declarative "Drivers" (JSON/YAML) to understand how to interact with them.
*   **Prompt Regex:** A regular expression defining what the CLI looks like when it is done thinking and waiting for the user (e.g., `^User:\s*$`).
*   **Initialization Sequence:** Commands to run on startup to bypass welcome screens.
*   **Sanitization Rules:** Specific loading spinner characters or ANSI codes to strip for this specific tool.

## 4. Component 3: The Stream Sanitizer
Interactive CLIs spit out massive amounts of control characters (move cursor up, clear line, change color to green). 
*   AgentHub implements a real-time stream parser (using libraries like `vte` or `strip-ansi-escapes`).
*   It buffers incoming bytes, strips terminal control codes, and extracts only the pure semantic text generated by the AI to display in the unified UI.

## 5. Component 4: The Central Message Bus
A `tokio::broadcast` channel that acts as the "Group Chat".
*   The Orchestrator reads from the sanitized CLI streams and broadcasts them as `AgentMessage` events.
*   The Orchestrator reads user input from the TUI, checks for tags (`@gemini`), and routes the text to the `stdin` of the corresponding PTY process.
